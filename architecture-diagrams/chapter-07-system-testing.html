7.1 Unit Testing

Unit Testing involves verifying the smallest testable parts of an application—such as isolated helper functions, algorithmic mathematical formulas, data sanitizers, and boundary checks—in total isolation from external network dependencies, live databases, or third-party cloud APIs.

Engineering & Academic Justification for Unit Testing

In SensAI, core business invariants—such as sliding-window rate limit window expiration, SHA-256 hash generation for binary PDF caches, SSRF URL whitelist filtering, and STAR prompt formatting—must function with mathematical determinism. Unit testing verifies these critical components under edge conditions (e.g., empty strings, null session claims, clock skew, and boundary quotas) without incurring the latency or financial expense of live third-party API invocations.

7.1.1 Testing Methodology & Tools

Unit tests were developed using Jest and Node Test Runner with isolated mocking for Redis keys and external API clients. Assertions verify return types, exception throwing behavior, and state immutability.

7.2 Functional Testing

Functional Testing is a black-box verification process that validates whether the system behaves in strict accordance with functional software requirements from the perspective of an end-user. It evaluates user inputs, button clicks, form submissions, state updates, and visual component renderings.

Engineering & Academic Justification for Functional Testing

While unit tests verify code logic in isolation, functional testing guarantees that user-facing features work as an integrated whole. For SensAI, it confirms that when a candidate uploads a resume, generates a cover letter, answers quiz questions, or completes a voice call, the user interface receives and renders the correct data, shows interactive loading states, and handles business rejections gracefully.

7.2.1 Testing Methodology & Scope

Functional test suites covered all 8 primary application modules across candidate workflows:

  • • Feature 01: User Authentication, Clerk Webhooks & Onboarding Form Submission.
  • • Feature 02: Industry Trends Dashboard, Salary Radar Chart & Skill Demand Insights.
  • • Feature 03: Interactive Resume Builder, Template Selection (5 templates), STAR AI Polish, and PDF Print Staging.
  • • Feature 04: ATS Resume Analyzer, PDF Stream Ingestion, 5-Pillar Score Card, and Improvement Radar.
  • • Feature 05: Tailored Cover Letter Generator, Markdown Editor Canvas, and One-Click Clipboard Copy.
  • • Feature 06: Technical Mock Quiz, Configurable Difficulty (10–25 questions), Timed Evaluation & Diagnostic Review.
  • • Feature 07: Real-Time WebRTC Voice Mock Interview, Bi-Directional Turn-Taking, and 6-Pillar Rubric Generation.
  • • Feature 08: Career Roadmap DAG Flowchart, Resource Video Embedding, and Milestone Checkoff.

7.3 Integration Testing

Integration Testing evaluates the correctness of interfaces, communication protocols, network boundaries, and transactional contracts between decoupled modules, third-party cloud services, caching tiers, and persistence databases.

Engineering & Academic Justification for Integration Testing

In modern serverless and cloud architectures, individual units frequently pass tests, but systemic failures occur at integration seams—such as Prisma database connection pooling timeouts, Redis sliding-window cache serialization desync, Gemini API prompt schema mismatches, and WebRTC signaling room teardown leaks. Integration testing validates that all sub-components operate cohesively as a resilient, fault-tolerant distributed system.

7.3.1 Critical Subsystem Interfaces Tested

  • • Interface 1: Next.js Server Actions <-> PostgreSQL Database via Prisma ORM (Foreign key constraints & cascade deletes).
  • • Interface 2: Next.js Server Actions <-> Upstash Redis (Sliding-window limiter and SHA-256 AI response caching).
  • • Interface 3: Next.js Server Actions <-> Gemini API (Multimodal base64 buffers and structured JSON schema parsing).
  • • Interface 4: Next.js Client SDK <-> LiveKit Voice Cloud <-> Python Voice Agent daemon (WebRTC audio sessions & room teardown).
  • • Interface 5: Subsystem 8.0 (Roadmap Milestone) <-> Subsystem 1.0 (User Profile) Skill Auto-Sync Feedback Loop.

7.4 Acceptance Testing (UAT)

Acceptance Testing (also known as User Acceptance Testing or UAT) is the final testing phase conducted in an operational, production-like environment with target end-users (job seekers, university graduates, and engineering candidates). Its goal is to determine whether the software fulfills real-world user expectations and is fit for production release.

Engineering & Academic Justification for Acceptance Testing

Technical correctness does not guarantee user satisfaction. Acceptance testing verifies that the AI feedback is genuinely constructive, that the voice interview feels natural rather than robotic, that resume exports print flawlessly on physical A4 paper, and that candidates can navigate the platform with minimal cognitive friction.

7.4.1 UAT Methodology & Candidate Cohort

Acceptance testing was conducted in two structured phases:

  • • Alpha Testing (Internal Cohort): Conducted by 5 developers and academic project reviewers to verify security edge cases, rate limiter UX, and responsiveness across Firefox, Chrome, Safari, and Edge.
  • • Beta Testing (Candidate Cohort): Conducted by an external cohort of 15 active job seekers across software engineering, data science, and product management domains.
